# `06` — ENGINEERING PRINCIPLES

### 01. Understand before changing.

> Código legado geralmente tem uma história que não está escrita no código.

### 02. Keep complexity intentional.

> Se uma abstração não resolve um problema real, talvez ela seja o problema.

### 03. Security is part of the architecture.

> Segurança não deveria aparecer depois que a aplicação está pronta.

### 04. Scale when it makes sense.

> Nem tudo precisa suportar milhões de usuários. Mas todo engenheiro deveria saber o que acontece quando o sistema cresce.

### 05. Software is a product.

> Uma API perfeita conectada a uma experiência horrível continua sendo um produto ruim.

### 06. Make it understandable.

> Código bom não é código que só você entende.
